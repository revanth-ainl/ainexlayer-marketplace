| `dodaios/marketplace/community_install.py` | plugin ids shipped in the seed catalog are reserved |

Three app-side findings, recorded for the app team (no app change made):

1. `publish.py._validate_mcp` still searches stdio args for `@1.2.3` or
   `:tag`. That refuses `uvx pkg==1.2.3`, which the installer accepts. The
   marketplace follows the installer.
2. `publish.py` does not require the plugin extension block; the installer
   does. The marketplace follows the installer, so such a plugin is refused
   here instead of listed and then failing to install.
3. `publish.py.validate_draft` never runs the installer's `convert_manifest`,
   so the app's own Publish button accepts a plugin whose auth block lacks a
   field its mode requires (for example `pat_paste` without
   `token_creation_url`), carries an unknown field, or has an invalid
   `longevity`; the installer then refuses it. The marketplace checks every
   auth mode against the app's `catalog.py` models, so such a plugin is
   refused here.

## 7. How to run the checks

```bash
python3 -I scripts/validate.py                       # every package + registry.json
python3 -I scripts/validate.py --base-ref origin/main  # plus ownership and version rules
python3 -I scripts/validate.py --submission issue.md   # one submission or app issue body
python3 -I scripts/compile_index.py --check           # the feed is up to date
python3 -I scripts/export_rules.py --check            # docs/rules.json and schemas/ are up to date
python3 -m unittest discover -s tests
../AIAgentLayer/.venv/bin/python -I -B tests/app_contract_check.py   # against the app, read-only
```

## 8. Completion, 2026-10-31

The open rows of section 6 were completed on `reconcile/2026-10-31` and the
branch was merged into the local `main` with `git merge --no-ff`. Nothing
was pushed. Added: `registry.py`, `hashing.py`, `schemas.py`,
`scripts/expand.py`, `scripts/export_rules.py`, `trusted-publishers.json`,
`docs/rules.json`, `schemas/` (8 files), `skills/README.md`,
`tests/app_contract_check.py` and five test modules. Changed:
`compile_index.py` (rewritten), `validate.py`, `registry.json` (format 2),
`docs/index.json` (regenerated: every existing field kept, revision 991113
to 991114), and the documentation.

Two decisions taken while completing it:

- AIAgentLayer sends a skill's version, title and categories as form fields
  and its SKILL.md template always says `version: 1.0.0`. `expand.py`
  therefore writes those listing fields into the frontmatter (where the
  feed reads them) instead of refusing the update; the rest of the SKILL.md
  is untouched. The frontmatter description is kept, with a warning when
  the submission's differs, and the submitted description is still checked.
- The four submission cases refused here but accepted by the app's Publish
  checks (frontmatter name differing from the package name, a reserved
  skill name, a reserved plugin id, `plugin_json.version` differing from
  the submission version) are stricter by design: each would install
  under another name, shadow a built-in, be refused at install, or publish
  a manifest that disagrees with its listing.

No `.github/workflows`, Dependabot, Pages, CNAME or git hook file exists, and
`validate.py` refuses them.
